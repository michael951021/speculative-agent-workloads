# Sweep batch 2 — T=0, k 1 ngram + k 2/4/8

## Issue
Main speedup table needs the measured tpc(k) curve: only k=1 cells (base/lora/lora_dpo/none)
exist. Without k=2/4/8 and ngram, "what speedup does speculative decoding buy" is unanswered
per drafter, and monotonicity in k is untested.

## Question
At T=0, does measured tokens-per-target-call increase monotonically with k for each model drafter,
and do the measured tpc(ngram k=1) and tpc(lora k=8) fall inside the alpha-metric CIs computed
on the same text? Refutation: a drafter with tpc(k+1) < tpc(k), or a measured tpc outside its
CI on the engine's own trajectory.

## Evidence
- results/sweep.parquet: ngram k1-8, tiny k1-4, base/lora/lora_dpo k=1, none done (393 each);
  remaining: tiny k=8 (392/393 in sidecar) + base/lora/lora_dpo k=2/4/8. wall ≈ 31-37 min/cell.
- Same-trajectory replay of ngram k=1 (check (c)) already PASSes: meas acc 0.4411 in
  [0.3990, 0.4807], tpc 1.1145 in [1.0981, 1.1313]. Measured tpc 1.1145 < pre-registered 1.15:
  coverage gap (engine sees only 16 fresh tokens per prompt; ngram proposes on ~26% of steps),
  not a measurement bug — replay == engine.
- At T=0 every emitted token is a target-greedy token, so the spec trajectory == the cached
  none trajectory (results/engine_traj_none.json) for ANY k and drafter (spec.py:206-210:
  accept iff draft == argmax p). Same-text metric check is therefore possible per k.
- Metric anchors: alpha_sweep_lora.json (corpus, ctx 0) tpc_valid_ci95 k=8 = [2.626, 2.648];
  batch 1 trajectory check passed at k=1 (meas 1.496, traj acc CI [0.5009, 0.5402]).
- Observed vs guessed: wall times/CI values above are observed; "~7 h for 13 new cells" is
  guessed from batch 1 per-cell wall.
